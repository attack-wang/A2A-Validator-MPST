**my recommendation: application**

here's my reasoning:

1 **interactive gameplay is essential**: the core mechanic requires a claw moving back and forth in real-time, with the player timing a grab this demands continuous user input, real-time rendering, and dynamic updates — something only an application can deliver

2 **game logic complexity**: the game involves object values, reeling-in timers, score tracking, level progression with ascending difficulty (more obstacles, tighter time limits), and win/lose conditions these need executable code, not static presentation

3 **visual feedback requirements**: the customer explicitly wants the position of the claw and objects displayed and updated after each grab an application (eg, built with python/pygame) can render the mining scene, animate the claw, and refresh the display every frame

4 **why not other modalities**: documents, powerpoint, pdfs, or images could only describe or mock up the game — they cannot be played a website could theoretically host a game, but the customer's request is best served by a standalone, self-contained application that runs reliably without browser dependencies
