Task:
Design a roguelike game inspired by Tower of the Sorcerer. Use a fixed 80x80 grid map. The player character is controlled using W/A/S/D keys for movement (up, left, down, right). The character can move only on floor tiles and cannot pass through walls. The goal is to reach the door to proceed to the next level. The player encounters monsters; combat is resolved by subtracting the monster’s HP from the player's HP. HP is restored by 20–30 points when the player touches a treasure chest. Ensure there is always at least one valid path from the starting position to the door. Include a minimal UI to display the player's current HP and encountered monster stats.

the customer is asking for an **interactive roguelike game** with these core characteristics:
- real-time keyboard control (w/a/s/d movement)
- a fixed 80x80 grid map with walls, floors, and doors
- turn-based combat resolution with monsters
- hp tracking, treasure chest pickups, and level progression
- a minimal live ui displaying hp and monster stats

these requirements demand a **runnable, interactive program** that responds to keyboard input and dynamically renders game state evaluating our available modalities:

- **image / document / powerpoint / pdf / mind map**: static formats — cannot support gameplay interactivity at all
- **excel**: not suitable for real-time game loops or keyboard-driven movement
- **dashboard**: designed for passive information display, not interactive gameplay

- **application**: directly supports visualized games via python (eg, pygame) — ideal for the 80x80 grid rendering, keyboard controls, combat logic, pathfinding guarantees, and ui overlays

therefore, i strongly recommend **application** as our product modality it is the only option that can fully realize the customer's gameplay requirements
