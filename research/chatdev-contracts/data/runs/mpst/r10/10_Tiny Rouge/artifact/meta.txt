Task:
Design a roguelike game inspired by Tower of the Sorcerer. Use a fixed 80x80 grid map. The player character is controlled using W/A/S/D keys for movement (up, left, down, right). The character can move only on floor tiles and cannot pass through walls. The goal is to reach the door to proceed to the next level. The player encounters monsters; combat is resolved by subtracting the monster’s HP from the player's HP. HP is restored by 20–30 points when the player touches a treasure chest. Ensure there is always at least one valid path from the starting position to the door. Include a minimal UI to display the player's current HP and encountered monster stats.

Modality:
as the chief product officer, i'd like to share my thoughts on the product modality for this task

given the customer's requirements — a roguelike game with an 80x80 grid map, real-time keyboard controls (w/a/s/d), turn-based combat with monsters, treasure chests, level progression through doors, and a minimal ui displaying hp and monster stats — i believe the most suitable modality is **application**

here's my reasoning:

1 **interactive gameplay**: the game requires continuous keyboard input handling and a game loop to render the grid, move the character, and resolve combat an application (eg, implemented in python with a rendering library) is naturally suited for this kind of real-time interactivity

2 **visualized grid rendering**: an 80x80 tile-based map with walls, floors, monsters, chests, and doors needs a canvas/grid rendering capability, which applications handle well

3 **game logic complexity**: pathfinding guarantees (ensuring at least one valid path to the door), combat resolution, and hp management are core program logic — best encapsulated in a standalone application rather than a static or document-based format

4 **cross-platform playability**: a python-based application can be run locally by the customer with minimal setup, delivering the complete gameplay experience as requested

while a website could technically host an html/js version of the game, the customer's description (keyboard-driven movement, local game session) aligns more closely with a desktop-style application, and it keeps the implementation robust and self-contained

what are your thoughts? do you agree that **application** is the right modality here?
